## Step 1(Native Approach)

- x < 0は、マイナス記号により、必ずfalse

まず以下の解法を考えた

1. 桁分の要素を持つ配列を作成　... 配列への代入に O(n)
2. 配列 Head(+= 1), Tail(-= 1)で確認していく

→ 2^31となると、Time complexity , Space complexity は大きくなってしまう

わからなかったので、解答を見てみると、**余りを用いてxを反転させた値を生成する方法**があるらしい

この方法で実装してみる。step1 で, leetcodeに提出はできた

## Step 2

色々と調べてみると、x が大きかった場合（2,147,447,412 < x  の32-bit符号付き整数）は、言語によっては Overflow を起こすらしい</br>
→ python の場合は, int は**多倍長整数**を採用しているので、自動的にメモリーが拡張されるらしい

#### 解）
数値の後半半分のみを反転させて、前半部分と比較する(桁数の偶奇に注意)</br>
→ こうすることで、余計な変数を増やさなくて済む
また、**末尾が0の場合**も、「-」と同様、Falseになる

## Step 3
Step1で元々考えた解法を改良するとLeetcode で最も計算が早いコードになるっぽい。以下の**文字列への変換**を使用するというものだった。

```python
str(x) == str(x)[::-1]
```

**Trade Off**
Space complexityを使用することで, time complexity を O(1)にする
